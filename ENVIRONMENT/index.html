    Environment variables¶

    The port reads a few hundred environment variables. Some are for players (upscaler, frame rate, controls). Most are diagnostics and developer switches. This page lists every variable found in src/, gpu/, bbsc/, scripts/, launcher/, run.sh, packaging/ and tools/, with what the code does with it. The information comes from the code on main (0.51-linux.16). When a comment and the code disagree, the code wins.

    How to set them¶

    In the launcher: go to Advanced → Developer → Extra variables (NAME=value, space-separated). The settings key is extra_env in the launcher's settings.json. The field is parsed in game_environment() (launcher/bbport_launcher.py:693):

    for item in s["extra_env"].split():
    if "=" in item:
        key, value = item.split("=", 1)
        env[key] = value
    • The field is split on whitespace. Each piece is split at its first =: BB_UPSCALER=fsr4 BB_AUDIO_GAIN=1.5 RADV_DEBUG=nohiz.
    • There is no quoting. A value cannot contain spaces, and quotes are kept literally as part of the value (BB_X="a" gives "a" with the quotes). Use separators the variable itself accepts, such as ; or ,.
    • A piece without = is ignored without any message. If a name appears twice, the last one wins.
    • Any name is accepted, including third-party ones (RADV_DEBUG, MANGOHUD, VK_*, __GL_*).
    • The result goes to run.sh. Both the launcher's Play button and --play (Steam shortcut, Steam Deck game mode) use it.

    From a terminal (source checkout): BB_GAME_DIR=/path/to/CUSA03173 BB_FPS=60 bash run.sh. Without the launcher, nothing sets the launcher's variables. run.sh then uses its own defaults (game folder ../CUSA03173, uncapped frame rate, and so on).

    From a terminal (AppImage): BB_UPSCALER=fsr4 ./Bloodborne-bbport-x86_64.AppImage --play starts the game with the launcher's saved settings. Mind the precedence below: the launcher's own settings replace a variable of the same name from the shell. Extra variables replace both. The AppImage keeps its data (bbport.ini, saves, logs) in BB_DATA_DIR, by default ~/.local/share/bbport.

    bbport.ini: many graphics options live in bbport.ini and the in-game menu, not in the environment. A few variables override those keys at start: BB_UPSCALER, BB_UPSCALE_PRESET, BB_FSR_SHARPNESS, BB_JITTER, BB_REACTIVE* and BB_OBJECT_MOTION (gpu/shim/bbport_settings.cpp:192-208). Values set this way stay in force until the next start.

    Precedence¶

    The environment is built in this order. A later step wins.

    1. The environment the launcher (or the AppImage) was started with.
    2. The launcher's own settings (game_environment(), launcher/bbport_launcher.py:619-698).
    3. Some are always written: BB_GAME_DIR, BB_MODS_*, BB_PROMPTS, BB_GESTURES_NO_MOTION, BB_PATCHES_*, BB_LANGUAGE, BB_REGION, BB_MENU_LANGUAGE, BB_FULLSCREEN, BB_PRESENT_MODE, BB_SKIP_NETWORK_CHOICE, BB_FPS, BB_DISCORD and BB_STEAM_OVERLAY. For these, a shell value is replaced.
    4. Others are written only when the setting is on or not empty: BB_HDR, BB_FPS_LIMIT, BB_DRAW_PIPE, BB_READBACKS, BB_PREUPLOAD, BB_PC_MODEL, BB_GPU_PROFILE, BB_PAD_DEADZONE (only when the dead zone is not 4 %), BB_PAD_LIGHTBAR and others. For these, a shell value survives while the setting is off.
    5. Hunter's Atlas (atlas_environment(), launcher/bbport_launcher.py:598): always BB_ATLAS_ENABLED (0 when the map is off or not prepared); with the map on also BB_MAP_DIR, BB_MAP_ART_DIR, BB_MAP_FONT, BB_MAP_CATALOG, BB_MAP_CONFIG, BB_MAP_TRAVEL_ENABLED, BB_MAP_ITEMS_ENABLED, BB_MAP_ITEM_CATEGORIES, BB_MAP_FOG_ENABLED=0 and BB_MAP_NPC_MODE=all.
    6. Online (only when Play online is on and the online module exists): scripts/online.py environment() adds BB_ONLINE, BB_SHADNET_*, BB_UPNP, BB_COMMUNITY_SERVER, BB_SEAMLESSHUNT_TOMBS, SHADPS4_P2P_* and the BBSC options (scripts/bbsc.py).
    7. Extra variables come last and override everything above, including the launcher's own settings and the BBSC options.
    8. run.sh mostly fills in defaults with ${VAR:-default}, so a value you set is kept. It does force a few:
    9. BB_AS_0_3=1 forces BB_GUEST_IN_PLACE=0, BB_HOST_COPY_WAITS=all and BB_PRODUCER_CHECK=1.
    10. BB_SAVE_LOG=1 forces BB_FRAME_STATS=1.
    11. BB_AUTO_RENDER_RES=1 makes run.sh unset BB_RENDER_RES, BB_OUTPUT_RES and BB_UI_RES, so do not set it by hand.
    12. When bbport.ini asks for a non-1080p output without live resolution and BB_RENDER_RES is unset, run.sh exports BB_RENDER_RES, BB_OUTPUT_RES and BB_DMEM_MB itself.
    13. BB_BBSC_LIB is unset unless BB_BBSC=1 and BB_ONLINE=1.
    14. SHADPS4_HTTP_HOST_OVERRIDES_JSON is rewritten whenever online play is on.
    15. BB_PRESENCE_DIR is rewritten when Discord is on, and BB_TROPHY_DIR when the trophy list is prepared.
    16. MANGOHUD is dropped while Steam's own performance overlay (mangoapp) runs.
    17. run.sh exports defaults that differ from the code's built-in ones: BB_COPY_GPU_BUFFERS=1, BB_GPU_WRITE_TWINS=1, BB_GPU_WRITE_TWINS_MAX=65536, BB_PREUPLOAD=1, BB_UFFD=0, BB_GUEST_IN_PLACE=$BB_PC_MODEL, BB_VBLANK_HZ (from BB_FPS) and BB_PC_MODEL (1 on AMD, 0 elsewhere).
    18. libbbsc sets BBSC_MOD_SEAMLESS=0 and SHADPS4_BBSC_FIVE_HUNTERS=0 itself on a public game server (The Hunter's Dream, nodreamforthehunter.com, shadps4.net or scej-network.jp; Seamless Hunt is not one), whatever was asked (bbsc/emulator/mod/linux/bbsc_mod_linux.cpp:360, the list in bbsc/emulator/mod/bbsc_http.cpp:245).

    Value formats vary from one variable to another:

    • The shadPS4-style Flag() (gpu/shim/core/emulator_settings.h:14) takes any value starting with 1, y or t as on.
    • Most port switches look at a leading 1, or treat everything but 0 as on.
    • A few logs and traps turn on when set to any value, 0 included.
    • BBSC switches are off only with 0.

    The Values column gives the rule for each variable. Where it says "(default X)", that is the behaviour when the variable is unset. In the tables:

    • Launcher: marks variables the launcher writes from a setting. Use the setting rather than the extra field.
    • Internal: marks variables set by run.sh or the package. Leave them alone.

    BB_PC_MODEL Memory model: 1 = new (default on AMD), 0 = the 0.3 one (default elsewhere).
    BB_DRAW_PIPE Two-stage GPU pipeline, 20–30 % faster: 1 on, 0 off (default on with 8+ CPU threads).
    BB_PREUPLOAD Background upload into VRAM: 0 off, 1 rewritten memory only (run.sh default), 2 everything (~3 GB more VRAM).
    BB_ASYNC_PIPELINES 0 makes the game wait for shader compiles instead of skipping a draw for a frame or two.

    BB_DLSS 0 turns DLSS support off on NVIDIA.

    BB_PAD_DEADZONE / BB_PAD_DEADZONE_OUTER Inner (default 5) and outer (default 127) stick dead zones, of 127 (launcher: Controls → Stick dead zone (%), the inner one).
    BB_MOUSE_DEADZONE Minimum stick deflection used for mouse look (default 16 of 127).
    BB_AUDIO_GAIN Master volume multiplier, up to 8 (default 1.0).
    BB_SAVE_LOG 1 saves the log and per-frame statistics to <data>/logs/ (for bug reports).
    MANGOHUD 1 shows the MangoHud overlay.
