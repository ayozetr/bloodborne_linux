    Environment variables¶

    The port reads a few hundred BB_* environment variables. Some are for players (upscaler, frame rate, controls); most are diagnostics and developer switches. The list below is every one the code reads, from the port's own registry (gpu/shim/bb_env_vars.def); tests/test_env_vars.py fails when the code and the registry disagree, so it stays complete. Everything from "Every BB_* variable" on is the output of python3 scripts/env_vars.py --doc (without its title); the sections above it are written by hand.

    How to set them¶

    In the launcher: Advanced → Developer → Extra variables (NAME=value, space-separated). The settings key is extra_env in the launcher's settings.json, read by game_environment() in launcher/bbport_launcher.py:

    • The field is split on whitespace, and each piece at its first =: BB_UPSCALER=fsr4 BB_AUDIO_GAIN=1.5 RADV_DEBUG=nohiz.
    • There is no quoting. A value cannot contain spaces, and quotes stay part of the value. Use separators the variable itself accepts, such as ; or ,.
    • A piece without = is ignored. If a name appears twice, the last one wins.
    • Any name is accepted, third-party ones included (RADV_DEBUG, MANGOHUD, VK_*, __GL_*).
    • The result goes to run.sh. Both the launcher's Play button and --play (a Steam shortcut, the Steam Deck's Game Mode) use it.

    From a terminal (source checkout): BB_GAME_DIR=/path/to/CUSA03173 BB_FPS=60 bash run.sh. Without the launcher, nothing sets the launcher's variables. run.sh then uses its own defaults (game folder ../CUSA03173, uncapped frame rate, and so on).

    From a terminal (AppImage): BB_UPSCALER=fsr4 ./Bloodborne-bbport-x86_64.AppImage --play starts the game with the launcher's saved settings. Mind the precedence below: the launcher's own settings replace a variable of the same name from the shell. Extra variables replace both. The AppImage keeps its data (bbport.ini, saves, logs) in BB_DATA_DIR, by default ~/.local/share/bbport.

    bbport.ini: many graphics options live in bbport.ini and the in-game menu, not in the environment. A few variables override those keys at start: BB_UPSCALER, BB_UPSCALE_PRESET, BB_FSR_SHARPNESS, BB_JITTER, BB_REACTIVE* and BB_OBJECT_MOTION (gpu/shim/bbport_settings.cpp). Values set this way stay in force until the next start.

    Precedence¶

    The environment is built in this order; a later step wins:

    1. The environment the launcher (or the AppImage) was started with.
    2. The launcher's own settings (game_environment()): some are always written (the game folder, mods, languages, frame rate, fullscreen and the like) and replace a shell value; others only when the setting is on.
    3. The launcher's Extra variables.
    4. run.sh, which fills in what is still unset (the data folder, the online module, Discord).

    Every BB_* variable the port reads, by kind, from gpu/shim/bb_env_vars.def (scripts/env_vars.py --doc). The game prints the variables set at its start (Environment: in the log) and warns about BB_* names it does not know.

    =1: ... / =0: ... / =N: ... say what that value does; set: ... means any value turns it on (even 0).
